# AGENTS.md

Guidance for AI coding agents (opencode, the Zed Agent, or any other tool that reads
`AGENTS.md`) working in this repository. Human-facing docs live in code comments; this
file captures the conventions that are implicit in the layout, the `justfile` and the
git history.

## What this repo is

A personal NixOS flake. `NixOS2501` is the active machine; `minimal` is a bootable
template used to provision new machines.

| Host        | Role                | Notes                                                                                    |
| ----------- | ------------------- | ---------------------------------------------------------------------------------------- |
| `NixOS2501` | Desktop PC (active) | imports the aggregate `modules/**/default.nix` plus `modules/tmp.nix` (scratch packages) |
| `minimal`   | template            | self-contained minimal host; copy to `hosts/<NewHost>` when adding a machine             |

`flake.nix` builds hosts via the `mkHost` helper and a shared `pkgsOverlay`
(`glaumarPkgs` from the `glaumar_nur` input, plus the `daed` `pnpm_10` workaround —
that workaround is annotated and must be preserved).

## Repository layout

```
flake.nix            # inputs + nixosConfigurations (hosts)
justfile             # canonical task runner — prefer these recipes over ad-hoc commands
.sops.yaml           # age recipients for secrets
chezmoi.toml         # system-wide chezmoi config (installed to /etc/xdg)
hosts/<Host>/        # per-host entrypoint (default.nix) + hardware-configuration.nix (generated)
modules/<domain>/    # domain folders; each has a default.nix that only imports its siblings
modules/tmp.nix      # scratch/temporary packages (Desktop only)
chezmoi/             # chezmoi source tree for dotfiles (dot_config/...)
secrets/             # sops-encrypted secrets (never plaintext)
.zed/                # Zed *project* settings (nixd LSP)
```

The dotfiles source of truth is the `chezmoi/` tree, not `~/.config`. `chezmoi.toml`
points `sourceDir` at `~/.nixos-config/chezmoi`; `dot_config/...` maps to `~/.config/...`
and the `private_` prefix applies `0600` permissions. Edit live config, then sync it back
into the repo (see below).

## Golden rules for agents

1. **Never commit or print secrets.** Everything under `secrets/` is sops-encrypted; treat
   `default.yaml` and `daed/wing.db` as opaque blobs. Do not `sops -d`, echo, or copy their
   contents. Never add a plaintext secret, key, or password anywhere in the repo.
2. **Do not run system-changing commands.** `just switch`, `nixos-rebuild switch`,
   `nix-collect-garbage`, `sops updatekeys`, and anything else that needs `sudo` mutates the
   live machine — do not run them unless the user explicitly asks. Validate with
   `nixos-rebuild build`, `nixos-rebuild dry-activate`, and `nix flake check` instead.
3. **Do not touch `hosts/*/hardware-configuration.nix`** — it is generated by `nixos-generate-config`.
4. **Keep `system.stateVersion = "24.05"`**; it is pinned to first-install and must not drift.
5. **Do not commit or branch on your own.** Leave changes in the working tree unless asked.
6. **Match the existing style** — minimal, focused edits consistent with surrounding code.

## Validation workflow

Run the narrowest check that covers your change, then broaden:

```sh
nixos-rebuild build            # evaluate + build the current host, no switch (preferred)
nixos-rebuild dry-activate     # simulate activation
nix flake check                # evaluate all outputs / both hosts
nixfmt <changed .nix files>    # format (this repo formats with nixfmt, not nixpkgs-fmt)
```

The `justfile` is the canonical entry point:

| Recipe                                                             | Effect                                                          |
| ------------------------------------------------------------------ | --------------------------------------------------------------- |
| `just switch`                                                      | `sudo nixos-rebuild switch` — **user-only, not for agents**     |
| `just update`                                                      | `nix flake update`                                              |
| `just dotfiles_sync`                                               | `chezmoi re-add` (pull live `$HOME` changes back into the repo) |
| `just daed_conf_sync`                                              | export `/etc/daed/wing.db` into the encrypted secret            |
| `just sops-edit` / `just sops-update-keys`                         | edit / re-key `secrets/default.yaml`                            |
| `just repair` / `just list-generations` / `just delete-generation` | maintenance (mostly `sudo`)                                     |

## Nix conventions

- One module per concern; each `modules/<domain>/` has a `default.nix` that **only**
  aggregates its siblings via `imports = [ ./a.nix ./b.nix ];`.
- Hosts are thin: they set host-specific options and `imports` the relevant modules.
  Host overrides use `lib.mkDefault` / `lib.mkForce` (see `modules/system/kde.nix`).
- Packages: `environment.systemPackages = with pkgs; [ ... ];`. KDE packages come from
  `with pkgs.kdePackages;`.
- Language servers, linters, formatters and toolchains live together in
  `modules/develop/languages.nix`, one server per format. Add new tooling there rather
  than to `modules/develop/default.nix`.
- Comments: **English**, and only where they explain non-obvious intent, constraints or
  workarounds (e.g. the `daed` `pnpm_10` override, the non-setuid `bubblewrap` note). Do not
  add comments that merely restate the code.
- Formatting is `nixfmt` (see the Zed `Nix` language config and `languages.nix`);
  use it for new/edited `.nix` files.

## Secrets (sops-nix + age)

- Encrypted values live under `secrets/`; recipients are declared in `.sops.yaml`.
- New secrets are wired up in a module via `sops.secrets.<name>` (see
  `modules/system/secrets.nix`, `modules/system/user.nix`, `modules/network/daed.nix`).
- Adding a key: add the public key to `.sops.yaml`, then `sops updatekeys secrets/**`
  (user-run; agents should not execute it).
- Never introduce plaintext equivalents; never widen `creation_rules` recipients.

## Dotfiles (chezmoi)

- Source tree: `chezmoi/` (`dot_config/...` → `~/.config/...`).
- Sync direction used here is `chezmoi re-add` (`just dotfiles_sync`): change the live file,
  then fold it back into the repo, then commit.
- `chezmoi.toml` is deployed system-wide by `modules/system/dotfiles.nix`; it deliberately
  keeps persistent state under `~/.local/state/chezmoi/`.

## Privacy (public repository)

This repo is published publicly on GitHub, so **everything committed is world-readable
forever, including git history**. Deleting a file in a later commit does not remove it: the
old `dotfiles/` tree is still fully retrievable even though it was dropped in `16ee4d2`.
Treat the history as the leak surface, not just the working tree.

- **Ask "would I publish this?" before adding any file — because it will be published.** If
  something sensitive was ever committed, consider it exposed; the only fixes are rewriting
  history (`git filter-repo`, then force-push) or making the repo private. Note that
  `glaumar` and `git@geekgo.tech` in commit metadata are intentionally public — do not
  "fix" that.
- **The encrypted `secrets/` blobs are safe only while the age private key is offline.** The
  ciphertext is downloadable by anyone; it stays private solely because
  `~/.config/sops/age/keys.txt` (and its backup) never leave the machine. Never commit an
  age/SSH private key, `keys.txt`, a passphrase, or any plaintext equivalent.
- **`chezmoi re-add` can pull in more than intended.** `just dotfiles_sync` folds live
  `$HOME` files into `chezmoi/`; keep it to declarative config and extend `.gitignore` for
  state/caches (browser profiles, token stores, `*-shm`/`*-wal` journals, recent-files,
  per-machine state). Do not sync personal media, notes, photos, or an avatar.
- **Commit the certificate, never its key.** `modules/develop/reqable-root.crt` is fine (a
  public root CA cert); the matching private key must never be added.
- **The machine is fingerprintable and that is accepted here.**
  `hosts/*/hardware-configuration.nix` (disk/partition UUIDs, swapfile offset, CPU) and
  `modules/system/locale.nix` (timezone) reveal the hardware layout and region. This is a
  personal machine, not a server, so it is intentionally published — but do not add further
  identifying data (serial numbers, MAC addresses, public IPs, extra hostnames).

## Zed / AI tooling setup (in-repo)

- `opencode` is installed system-wide (`modules/develop/default.nix` under `# AI`, and
  `modules/develop/zed.nix` where it is documented as "ACP agent used by Zed").
- Zed talks to it over ACP: `agent_servers.OpenCode` → `opencode acp`, default `mode: build`,
  `effort: high`, model `opencode-go/deepseek-v4.1-flash`.
- The agent's runtime config (sandbox, tool permissions, model) is the **chezmoi-managed**
  file `chezmoi/dot_config/zed/private_settings.json` (→ `~/.config/zed/settings.json`,
  mode 0600). Edit that file to change agent behaviour; the repo-local `.zed/settings.json`
  only configures the `nixd` LSP for this project.
- Sandbox: `bubblewrap` must be a **non-setuid** binary on `$PATH` (do not install it via
  `security.wrappers`). Agent writes are limited to `/tmp`; network access is allow-listed;
  `allow_unsandboxed = true` lets the user opt into unsandboxed commands.
- To avoid permission prompts, agents should prefer commands already in the terminal
  allow-list (`git`, `ls`, `cat`, `rg`, `sed`, `nu`, `nix eval|build`, `nix flake …`,
  `nixos-rebuild build|dry-activate`, `chezmoi diff|status|…`, `nixfmt`, …) and use `/tmp`
  for scratch files. `fetch` is allow-listed for github, zed.dev, rust-lang, nixos.org,
  stackoverflow and similar docs hosts.

## Commit messages

Use Conventional Commits with a short scope naming the area, matching recent history:

```
feat(nushell): add carapace for external command argument completion
fix(zed): install bubblewrap for Agent sandbox
refactor(develop): consolidate language tooling into languages.nix
chore(ghostty): bind global quick terminal to super+enter
```

Scopes seen: host-agnostic areas and module names (`nushell`, `shell`, `zed`, `ghostty`,
`flake`, `develop`, `system`, `kde`, `flatpak`, `network`, `game`, `multimedia`). Keep the
subject imperative and lower-case; explain the _why_ in the body for workarounds.

## Common tasks

- **Add a host**: copy `hosts/minimal` to `hosts/<NewHost>`, regenerate its
  `hardware-configuration.nix` on the machine, set `networking.hostName` and user
  credentials, then add `mkHost { systemModule = ./hosts/<NewHost>/default.nix; }` to
  `flake.nix`.
- **Add a package**: pick the domain folder (`modules/system`, `develop`, `game`, …) and add
  it to `environment.systemPackages`. Temporary experiments go in `modules/tmp.nix`.
- **Add a new module**: create `modules/<domain>/<thing>.nix` and add it to that domain's
  `default.nix` `imports`.
- **Add a secret-backed file**: declare `sops.secrets.<name>` in a module, reference
  `config.sops.secrets.<name>.path`, and ask the user to run the `sops` recipe.
- **Change dotfiles**: edit under `chezmoi/`, then note that the user runs `just dotfiles_sync`.
- **After editing Nix**: run `nixos-rebuild build` (or at minimum `nix flake check`) and
  `nixfmt` before finishing.
